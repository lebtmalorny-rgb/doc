# Проверка комплекта — 14.10.2026

При публикации в `doc` 15.10.2026 из копии комплекта повторно выполнены:
20 unit tests, integration (включая syntax-check), проверка AST Python 3.8,
пять Bash-примеров README через `bash -n` и проверка локальных Markdown-ссылок.
Все проверки прошли; код сборщика не изменялся.

Проверки выполнены локально на macOS. Контроллер: ansible-core 2.18.2,
Python 3.13.3; тестовый runner: Python 3.14.0. Синтаксис исходников дополнительно
проверен Python AST с `feature_version=(3, 8)` — это не исполнение под Python 3.8.

| Проверка | Результат |
|---|---|
| `python3 -m unittest discover -s tests -v` | 20 tests PASS |
| `python3 tests/integration.py` | PASS, включая встроенный `--syntax-check` |
| Ограниченный inventory | В результате только узлы из `--limit` |
| Первый узел недоступен | Остаётся в summary; результат доступного узла сохранён |
| `--check` | Явный отказ, каталог результатов не создаётся |
| Конфиденциальность | Проверены projection inspect/INI, escaped secrets, длинные строки |
| Таймауты | Проверены output cap, закрытые pipes, отложенное завершение после kill |
| Docker guard | Проверены несовпадающий FD и подтверждённый владелец socket |
| Ошибки параметров | Ошибка ISO-8601 сохранена без полного Ansible exception |
| Артефакты | Private files 0600; run/records/hosts dirs 0700 |

В integration применяется временный fixture module; недоступный узел —
loopback `127.0.0.1:1` без SSH proxy/config пользователя. Затем проверяется
реальная упаковка Ansible module с невалидным параметром, до начала сбора.
Linux sysfs/process/config/runtime ответы моделируются только на границах
в unit tests; настоящие команды управления контейнерами не исполнялись.

Пять важных замечаний независимого review устранены с регрессионным покрытием:
формат времени journalctl, маскирование экранированных кавычек, производительность
маскирования длинных строк, проверка владельца Docker socket и ограничение
ожидания завершения после SIGKILL.

**Не проверено:** запуск на production Linux/Kolla/PVS, фактические ответы
конкретных версий Docker/Podman, состояние mapping Dorado, API OpenStack,
live attach/detach, полнота журналов конкретного инцидента. PASS локальных
тестов не является заключением об исправности инфраструктуры.
